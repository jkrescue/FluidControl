# FC-P008 approval — train-only full-family force-readout recalibration

Recorded 2026-10-05 Asia/Shanghai before implementation outcomes. Lead approval currently covers implementation and CPU tests only. Feature extraction, checkpoint production, formal evaluation, PPO and real-CFD execution require later review and explicit approval.

## Hypothesis

The frozen FC-P003C FNO representation may contain a more stable train-only four-force readout when all existing training families are used, instead of fitting only the train8 prefix panel. This experiment tests readout identifiability and phase transfer; it does not change the FNO architecture, field prediction, training data, normalization, control reward or scientific admission thresholds.

## Fixed data and weighting contract

- Use all and only the existing train-only H1 endpoints from 44 trajectories: base20 `N=16000`, train8 `N=1600`, and train16 `N=2048`, total `19648`.
- The family shares are fixed from the existing regular sampler window ratio, in family order base20/train8/train16: `(720, 408, 240) / 1368`. They are not the H1 endpoint counts.
- Each endpoint in family `f` receives global weight `share_f / N_f`. Fold scores are aggregated over out-of-fold predictions with these global endpoint weights. A fold that lacks a family is not first made into a per-family or per-fold equal-weight score.
- All standardization statistics are computed from that fold's training rows only. The final selected-alpha fit recomputes statistics on all train-only rows.

## Canonical phase and leakage guard

The four folds are physical source phases, not case-name or episode-name groups. The reviewed mapping artifact is `artifacts/fcp003c_full_train_source_phase_mapping_20261005/mapping.json`, SHA-256 `57ed2a25eed41ff25f75aad529e4186f66d952053ddd7adcfff9517291693b92`:

- canonical b00: source time 148;
- canonical b02: source time 106;
- canonical b04: source time 120;
- canonical b06: source time 134.

Base20 and train8 are joined using source restart/state identity and start time. Train16 b00/b02 are admitted to those folds only through the audited source case/time mapping plus curated frame-0 identity; episode names alone are insufficient. Any unmapped, ambiguous, or inconsistent row is a fail-closed error.

## Numerical and selection contract

- Extraction and native replay use the formal deployment numerical protocol: default TF32/high throughout. The earlier highest-FP32 diagnostic is not the deployment route and its coefficients are not reused.
- Use the fixed alpha grid `{0, 1e-8, 1e-6, 1e-4, 1e-2, 1}`. Select by the globally weighted four-fold out-of-fold metric; exact ties choose the larger alpha. The all-train endpoint inventory necessarily includes the former train8 late window; those rows are ordinary train rows in FC-P008. Prior late-window results must not be used to change the grid or selection rule. Validation and frozen data cannot select alpha or be read.
- Refit once on all train-only rows using the selected alpha.
- Produce a new checkpoint by changing only the four force-output rows. Every other model tensor must remain byte-identical. The saved checkpoint must use the official save path. Under default TF32/high, the strict `2e-5` wiring check uses the captured native execution order (pointwise force head, then masked mean); ideal pooled-feature affine versus native replay differences are reported for all four channels, not assumed algebraically identical. Native replay over the full train inventory must be finite, the state output must remain unchanged, and row confinement plus official save/reload must pass before any formal-evaluation request.
- No validation, frozen, PPO or real-CFD data may be enumerated or read.

## Required implementation evidence and exit criteria

CPU tests must cover the exact 44-trajectory inventory and family counts, global endpoint weighting, fold-train-only statistics, physical phase grouping across families, train16 episode-name rejection, fixed alpha/tie behavior, coefficient de-standardization, and checkpoint row confinement. Captured-order native replay and official checkpoint save are GPU-execution concerns and are not authorized by this approval.

Implementation/CPU-test acceptance only means the experiment is ready for a later execution review. A future produced checkpoint remains scientifically unqualified until the unchanged field, force, rollout, window and development gates are run. Software readiness or a low train-only out-of-fold score does not authorize PPO.
