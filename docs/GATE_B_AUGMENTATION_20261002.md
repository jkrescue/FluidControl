# Gate-B high-rotation CFD augmentation

The 10-epoch PhysicsNeMo multistep FNO lowered the standard holdout's
100-step total-drag NRMSE from 16.18% to 13.56%, still above the fixed 10%
Gate-B limit. The largest case-level error is `expanded_test_04` (28.13%);
several high-error 100-step segments have mean absolute rear rotation 4.5–5.
This motivates additional high-rotation action histories, but the association
does not prove that action coverage is the only cause of error.

## Physical CFD case

Each new run starts from the same validated `t=80` OpenFOAM restart. The two
fixed, equal-diameter cylinders have centres `(10, 7.5)` and `(15, 7.5)`, so
`L/D=5`. The flow is two-dimensional, incompressible, `Re=100`, with
kinematic viscosity `0.01` and `D=U∞=1`. The rear cylinder rotates with an
OpenFOAM linearly interpolated `rotatingWallVelocity` table; the centres do not
move. The action is bounded by `|ω|≤5` and its maximum rate by the existing
training coverage, `6.667`. `pimpleFoam` in the pinned OpenFOAM v2512 container
solves `t=80..160` with `Δt=0.005` and saves `U,p` every `0.1` time unit.
Front/rear Cd and Cl and 32 wake velocity probes are retained.

Three action schedules were fixed before running the CFD; they are distinct
from all previous actions and each other:

| Case | Role | Seed | Sampled ω RMS | Max |dω/dt| |
| --- | --- | ---: | ---: | ---: |
| `expanded_train_24` | training | 2026100408 | 3.6564 | 4.667 |
| `expanded_train_25` | training | 2026100428 | 3.6437 | 6.000 |
| `expanded_test_05` | new frozen test | 2026100520 | 3.6274 | 4.667 |

The last case is a new untouched test because the original test 04 was used
to diagnose and design this augmentation. Do not train, tune or select a
checkpoint on test 05. The fixed Gate-B threshold remains 10%; report its
error separately and retain the original four-case aggregate for comparison.
All three are generated by
`cfd/tandem_cylinders/make_gate_b_augmentation.py`; the deterministic action
audit is `artifacts/tandem_cylinders/gate_b_augmentation_schedule_audit.json`.

## Solver and data checks

The cases run in the pre-existing isolated OpenFOAM container with a read-only
root, no network, no GPU, four CPU cores and 8 GiB memory per case. The normal
expanded-case validator checks exactly 16,000 time steps, solver completion,
Courant number below 1, global continuity error below 1e-5, 801 saved field
frames, complete probe and force histories, and action bounds. The combined
run log is `artifacts/tandem_cylinders/gate_b_aug_cfd.log`; it ended with
`EXPANDED_CFD_CHUNK_OK expanded_train_24 expanded_train_25 expanded_test_05`.

`scripts/build_gate_b_aug_v3_spark.sh` exports all new field frames as VTK,
uses the official PhysicsNeMo Curator `VTKSource` and `Mesh` sampler to produce
HDF5, and hard-links the 32 already validated v2 trajectories. The resulting
immutable profile has 26 train, 4 validation and 5 test trajectories, each
with 801 frames at a 256×128 grid. Normalization is recomputed from training
only. Before use for FNO, the script requires raw action/force label parity,
per-frame finite fields, exact split counts, duplicate-signature rejection,
and controlled-CFD response checks. Canonical data and audit files remain on
the primary Spark; the compute Spark only receives temporary train/validation
input for model training.

All trajectories share one geometry, Reynolds number, coarse mesh and source
restart, so this augmentation tests unseen *control histories* within the
same physical setup. It is not an experimental dataset or evidence of
geometry/mesh generalization or achieved drag reduction.

### Restart-boundary force-label provenance

The first full-dataset parity check caught a validator error: for the three
new restart cases the exact force label at `t=80` comes from the source
OpenFOAM case, because the restarted `coefficient.dat` begins at `t=80.005`.
The validator now joins that single source row before interpolation. The new
cases pass the unchanged `1e-5` force-label tolerance, with maximum error
below `4.8e-7` across all 801 frames.

The 32 inherited v2 HDF5 files use a different historical convention: their
first `t=80` force label equals the first restarted sample at `t=80.005`, not
the exact source-case force at `t=80`. This is a **known first-frame label
offset**, not a CFD field error. The v3 validation accepts it only when that
label matches the first raw restart sample within `1e-5`; the other 800 frames
must match the exact raw OpenFOAM interpolation within `1e-5`. The validator
reports `legacy_initial_force_error` for each inherited case. No raw or HDF5
file is silently edited. This affects 32 of 28,035 total frames and must be
reported with any scientific evaluation using v3.

After `GATE_B_AUG_V3_CURATED_OK`, the guarded
`scripts/advance_after_gate_b_aug_v3.sh` runs one full training epoch as a
technical smoke test and then trains the official seven-output PhysicsNeMo
FNO for 30 epochs from scratch on the recomputed v3 normalization. This avoids
silently loading a checkpoint trained under the earlier v2 normalization.
The primary GPU remains subject to the same 20 GiB unified-memory floor and
0.20 per-process CUDA allocator cap. The smoke/formal logs and completion
markers are placed in `artifacts/tandem_cylinders/`; the selected model lives
under `artifacts/tandem_fno_gate_b_aug_v3_30epoch/`.

After formal one-step training, `scripts/evaluate_gate_b_aug_v3_onestep_spark.sh`
runs the unchanged 1/10/50/100-step observed, zero-action, sign-flipped and
shuffled-action panels on all **five** v3 test histories. It also evaluates the
independent shedding-phase case using v3 train-only normalization and writes
the fail-closed Gate-B audit. A separate observed-action evaluation on the
original four-case test cohort permits like-for-like comparison with v2.
`gate_b_v3_comparison.json` reports the five-case aggregate, original four-case
aggregate and fresh test 05 individually; a favorable original four-case
result alone cannot be treated as fresh independent validation.
