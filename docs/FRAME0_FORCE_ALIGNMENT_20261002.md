# Curated frame-0 force alignment audit (2026-10-02)

The 32 real-CFD trajectories in `tandem_cylinders_expanded_independent_v2` share the genuine OpenFOAM t=80 restart. Their first curated field frame is timestamped t=80, but the expanded-case `forceCoeffs` function object writes its first sample at t=80.005. The original Curator recipe used `numpy.interp`; for a requested time before the first coefficient row, that returns the first available t=80.005 value. Consequently the original HDF5 frame-0 force is **real CFD, but time-misaligned**, not the force at the field timestamp.

The [32-case audit](results/tandem_frame0_force_alignment_audit_20261002.json) confirms that each HDF5 frame-0 rear Cd/Cl matches its first expanded-case CFD coefficient to within 5.9e-8, while the maximum difference from the actual source-case t=80 rear force is 0.00755. The [HydroGym reset parity result](results/tandem_frame0_adapter_parity_verified_20261002.json) shows the corrected adapter now reads the original source-case force at t=80: rear-force difference 0, wake-probe maximum difference 0.00112 (within the existing 0.02 field-sampling tolerance), and exact action parity. The CPU-only check used the five-epoch frozen checkpoint to test the adapter interface; it is not a 20-epoch performance result.

The current v2 HDF5 files are **not overwritten**, so the running 20-epoch training and its provenance stay intact. PhysicsNeMo's one-step DataPipe uses the *following* frame's force as its target, not frame 0; the direct force target is therefore unaffected. The original normalization statistics did include frame 0, so a future fully clean publication dataset should be re-curated and retrained. The Curator source recipe has been updated to prepend the exact baseline t=80 force row before alignment whenever a restarted case has no coefficient at its first field time; it fails closed if that provenance is missing or the force series does not cover the field times. This fix applies to future generated data, not retroactively to v2.

For the ongoing HydroGym PPO pilot, `TandemSurrogateFlow` now loads the true source-case t=80 force only for frame 0 and explicitly records `initial_force_source`; later frames continue using their time-aligned HDF5 force. The actual real-CFD feedback runner already initializes from the source-case t=80 observation. The independent FNO test/action-sensitivity screen and medium-mesh numerical study remain separate requirements before a control-benefit claim.
