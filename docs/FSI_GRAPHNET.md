# FSIGraphNet 项目文档

唯一的项目文档：目标、模型、训练、推理、数据、评估指标、当前结果、使用方法、开发记录，以及当前调试状态与下一步计划（第 10 节，供接手者直接继续）。

## 1. 目标与原则

- **场景**：Re≈100 的串列双圆柱，间距 5D。前柱固定；后柱横向弹性支撑，自由振动（m = 0.7854，c = 0.019739，k = 1.24025），表面给定转速 ω = ±0.1 rad/s。网格只随后柱平移。
- **参考数据**：OpenFOAM pimpleFoam，13,824 个四边形单元，宏步 Δt = 0.1 s。
- **模型**：以 MeshGraphNet 为主体的流固耦合联合预测网络。一次前向计算同时输出下一时刻的流场和结构状态，多步预测时把输出作为下一步的输入，自主推进。
- **物理的作用**：物理方程只出现在两处。一是训练损失；二是网络内部的显式反馈，即对预测结果直接算物理残差，再作为特征输入网络。推理时不求解方程，不做投影或压力泊松，也不做流固不动点迭代或任何按收敛判断的循环。
- **原则**：
  - 不构造数据，不用 CFD 结果替代或重置预测。
  - 训练与推理是同一个网络、同一条前向路径。
  - HELDOUT 只用于最终验收。
  - 使用 FP32，物理计算用 FP64。

## 2. 模型（`src/fsi_mgn/`）

配置见 `configs/fsi_graphnet.json`：hidden 128，共 6,274,312 个参数。物理层没有参数。

| 部分 | 定义 |
|---|---|
| 流体节点 | 13,824 个单元，28 维特征：Uⁿ、两个历史增量、pⁿ、Δp、log 体积、到两柱的相对位置和对数距离、边界面法向汇总、工况 (Re, ω, U∞) |
| 流体边 | 27,344 个内部面 × 2 个方向，9 维特征：方向、对数距离、面法向、对数面积、面通量、通量增量、网格运动通量 |
| 结构节点 | 1 个，12 维特征：y、v、a 及上一步的值，log m / log c / log k，ω、Re、U∞ |
| 壁面边 | 后柱壁面 64 个面，连接壁面单元与结构节点，双向传递消息；8 维特征 |
| 处理器 | 3 个耦合阶段。每个阶段：1 个细网格消息传递块 → 图 U-Net（13,824 → 3,450 → 860 → 215 个簇，每层 2 个粗图块，最粗层做 4 头全局自注意力）→ 1 个细网格块。每个块同时更新流体边、壁面边、流体节点和结构节点 |
| 时间记忆 | 每个单元一个 64 维 GRU 隐状态，跨时间步携带；推理开始前用最后 8 帧已知数据预热 |
| 阶段间物理反馈 | 每个阶段结束时解码出临时预测，计算显式物理量：壁面力、R_FSI、连续性、壁面无穿透、滑移、Newmark 残差。这些量编码后加回网络，进入下一阶段。阶段数固定为 3，不判断收敛 |
| 流场输出 | ΔU、Δp → Û = Uⁿ + s₁ΔU，p̂ = pⁿ + s_dp Δp；内部面通量 = interp(Û)·S + 网络修正；壁面通量 = 网格运动通量 + 网络修正 |
| 结构输出 | â = a_eq(F_y) + 网络修正。a_eq 是 Newmark（β = 1/4，γ = 1/2）下 m a + c v + k y = F_y 的闭式解，其中 F_y 来自本阶段网络预测的流场。y、v 由 Newmark 关系得到 |
| 网格 | 按 ŷ 平移；平移权重由最后两帧已知网格识别 |

结构性检查：`tests/no_solver.py` 确认模型只依赖 torch、numpy 和标准库，前向路径中没有任何求解调用。`tests/smoke.py` 确认训练与推理的前向结果逐位相同。

## 3. 训练（`fsi_mgn_train.py`）

- **窗口**：先取 20 帧已知数据；网络自主推进 burn-in 步（不求梯度）；再自主推进 H = 8 步，计算损失并反向传播。
- **自滚动长度**：16–64 步，第 51 次更新起改为 32–128 步，约 0.25–2 个涡脱落周期。这样网络能见到自身长程误差积累后的状态。
- **数据项**：用 CFD 作为标签，与网络预测同一时刻。包括 u、Δu、网格尺度误差、p、面通量、涡量、y、v、a、F_y / F_p / F_v、近壁压力、压力和升力增量。
- **物理约束**：增广拉格朗日，以容差为单位，λ·h/tol + ρ/2·(h/tol)²。约束项为 R_FSI = m â + c v̂ + k ŷ − F_y(Û, p̂)、连续性、壁面无穿透；另有 Newmark 运动学一致性，以及"残差应逐阶段下降"项。
- **低频偏置项**：窗口内升力和位移平均误差的平方，权重 2（`mFy`、`my`）。
- **升力振荡项**（`sFy`、`mP`）：窗口内升力标准差与 CFD 之差，以及升力功率 F_y·v 的窗口均值（能量传递）与 CFD 之差，均取平方。发布配置中权重为 0；微调配置 `configs/finetune_lift*.json` 中为 5 和 10。
- **耦合阶段权重**：0.25 / 0.5 / 1.0。
- **优化器**：AdamW，lr 1e-4（热启动），预热 10 次更新后余弦衰减；梯度裁剪 1.0。
- **并行与精度**：torchrun 4 rank × 每 rank 6 个窗口；严格 FP32，确定性算法。
- **约束本身无偏**：在 CFD 真值上算出的残差（`tests/physics_truth.py`）为 F_p 精确一致，F_y 0.4 %，R_FSI 0.45 %，连续性 9e-10，壁面无穿透 3e-7，Newmark 1e-5 m。

## 4. 推理（`fsi_mgn_infer.py`）

- **输入**：一个工况目录，只读取前 20 帧已知数据作为初始状态，另外读取网格和工况常数。
- **计算**：每步一次前向，内含 3 个固定耦合阶段。
- **输出**：每步的 y、v、a、F_y、R_FSI 和耗时；加 `--fields` 时另存 U、p、涡量场。
- **速度**：GB10 单卡 FP32 每步 0.40 s。

## 5. 数据与划分（`data/splits/fsi_viv.json`）

- **来源**：OpenFOAM pimpleFoam 二维不可压动网格模拟，13,824 个单元，每 0.1 s 保存一帧；ρ = 1，ν = 0.01，D = 1，因此 Re = 100 U∞。
- **基准组**（6 例）：Re 100、ω = ±0.1，C、E、F 是三次独立的 CFD 运行，最终进入同一极限环，相位不同；每例 333–341 帧。
- **来流组**（20 例）：在 t = 143.2 s 从基准运行 C/E 分支出来，只改变入口速度（U∞ 0.75–1.10），适应 160 s 后记录 40 s；每例 401 帧。
- **合计**：26 例，约 10,000 帧。U∞ = 1.2 的 2 例因位移超过 0.5D 被排除。

| 角色 | 工况 | 说明 |
|---|---|---|
| TRAIN（14） | 基准 C±、E±；来流 C±，U∞ 0.75 / 0.8 / 0.85 / 0.9 / 1.1 | 训练 |
| VAL（6） | 来流 E±，U∞ 0.8 / 0.9 / 1.1 | 选择 |
| DEV（2） | 基准 F± | 与训练同工况（Re 100）的独立运行，不是新工况 |
| HELDOUT（4） | 来流 C±，U∞ 0.95 / 1.05 | 训练中从未出现的工况，只用于最终验收 |

训练只使用 TRAIN；`tools/launch_train.py` 拒绝其他角色。

## 6. 评估指标体系

评估方式：从 20 帧已知数据出发，全自主强耦合预测 300 步（约 4.7 个周期），中途不做 CFD 修正。逐周期统计按 CFD 位移上穿零点切分。

| 层 | 指标 | 目标 |
|---|---|---|
| A 结构响应 | A1 振幅比 | 1 ± 5 % |
| | A2 振幅增长率 | 1 ± 3 % |
| | A3 频率比 | 1 ± 2 % |
| | A4 相位误差 | ≤ 10° |
| | A5 位移相关 | ≥ 0.98 |
| | A6 升力均值偏差 | ≤ 10 % |
| | A7 升力 RMS 比 | 1 ± 10 % |
| | A8 升力–位移相位差 | ≤ 5° |
| | A9 能量传递误差 | ≤ 5 % |
| | A10 两柱 C_D 均值、C_L RMS | ± 5 % |
| B 流场精度 | B1 脉动归一化误差 | 65 步 ≤ 0.5；300 步 ≤ 1 |
| | B2–B4 RMSE、MAE、Rel L2、R² | R² > 0 |
| | B5 场相关 | 150 步 ≥ 0.7 |
| | B6 涡量误差 | 300 步 ≤ 0.5 |
| C 流场统计 | 分频段 fRMSE、FE、KE、MVPE、尾迹 Strouhal 数、近壁网格噪声 | — |
| D 物理一致性 | R_FSI、连续性、壁面无穿透、Newmark 残差、逐阶段下降 | 与 CFD 残差底比较 |
| E 长程稳定性 | 结构有效时长 ≥ 4 周期；流场有效时长 ≥ 65 步；误差增长率 ≈ 0；1000 步不发散 | |
| F 泛化与效率 | 跨工况分布、HELDOUT 验收、推理速度 | |

B、C 层采用 RealPDEBench（arXiv 2601.01829）的定义。A 层参考 VIV 响应参数（Williamson & Govardhan 2004）以及 FSI 代理模型的能量传递指标（arXiv 2511.22012）。A 层由 `src/fsi_mgn/metrics.py` 计算，并随每次评估输出。

## 8. 使用方法

- **配置**：`configs/fsi_graphnet.json` 包含模型和训练的全部超参数，对应发布模型。`configs/finetune_lift.json`（H = 8）和 `configs/finetune_lift_h16.json`（H = 16，2 rank，lr 3e-5）是在其上叠加的微调配置，分别复现实验 V17A、V17B。
- **代码发布**：`tools/release.sh <tag> <root>` 把 git 标签导出到 `<root>/code_releases/<tag>`（只读，附带逐文件 SHA 清单）。训练和评估运行时复制并校验这份代码。
- **训练**：
  1. `tools/make_recipe.py [--config <配置>] <root> <run_id> <tag> [<init checkpoint>]` 生成配方；init 路径相对 `experiments/runs`。
  2. `tools/launch_train.py <root> <recipe>` 在容器中启动 torchrun。
  3. 运行目录为 `experiments/runs/<run_id>/{contracts, results, control}`。在 `control/` 下创建 `STOP` 文件即可停止训练。
- **评估**：`tools/eval_checkpoint.sh` 等待指定 checkpoint 生成后，用 `tools/launch_eval.py` 评估，并用 `tools/render.py` 出图；`tools/eval_milestones.sh` 依次处理各里程碑。
- **数据目录**：`<root>/data/processed/<dataset>/<case>/{sequence.npz, report.json}`，启动时逐文件校验 SHA。训练只使用划分中的 TRAIN 工况。
- **资源**：每台机器保留 ≥ 10 GiB 空闲内存。H = 8：每 rank 约 14 GiB，4 rank 每次更新约 2 分钟；H = 16：每 rank 约 28 GiB，2 rank 每次更新约 1.5 分钟。300 步评估约 2 分钟（0.40 s/步），另需约 20 GiB 空闲内存。


## 9. 开发记录

| 阶段 | 变化 | 结果与结论 |
|---|---|---|
| 求解器加修正（已停止） | 每步在动量方程、投影、压力泊松、流固迭代等求解器之上做网络修正 | 实际是求解器为主、网络为辅，推理也需要求解与迭代，因此改为以网络为主体 |
| 联合预测网络 | MeshGraphNet：3 个耦合阶段 + 显式物理反馈 + 增广拉格朗日约束 | 一步前向，不求解 |
| 多尺度 | 图 U-Net | 感受野覆盖全域 |
| 载荷监督 | 壁面载荷与增量监督 | 解决升力冻结（此前预测升力从第 1 步起几乎不变） |
| 结构头 | 运动方程闭式基准 + 网络修正 | 解决结构自由漂移（此前位移在第 1 周期内超过 1 m） |
| 记忆与全局交互 | 最粗层全局注意力 + GRU 时间记忆 | 尾迹不再冻结；第 1 步误差 0.35 → 0.23 |
| 输出滤波（未采用） | 固定输出滤波 + 近壁损失 | 无改善 |
| 长程训练（V15 → V16） | 长程自滚动训练 + 低频偏置损失 | 只用短窗口训练时，越训练长程误差越大（第 300 步 3.96 → 9.15），第 3 周期起升力正向漂移、周期短 12 %、振幅发散。改进后 V16A 训练 50 次更新：相位锁定，振幅不再发散，第 300 步误差 2.32，作为发布模型。V16A 继续训练到 100 次反而振幅更小（第 4 周期 0.63）；V16B（更长自滚动、偏置权重 4）振幅发散到 1.58 |
| 升力振荡约束（V17，进行中） | 从发布模型热启动，损失加入升力标准差 `sFy` 与升力功率 `mP`；V17A 用 H = 8，V17B 用 H = 16 | 振幅衰减已解决；H = 16 流场明显更好；出现频率偏高、相位超前，随训练部分收敛，见第 10 节 |

经验：
- 使用原生单元图，避免单元与节点之间的插值误差。
- 训练必须见到网络自身推进后的状态，且推进长度要覆盖误差显现的时间尺度（约 2 个周期）。
- 只靠逐步损失，约束不住慢变偏置、振荡强度和频率；需要窗口级统计量（均值、标准差、功率）作为损失。
- 训练更多不一定更好：每个里程碑都要做 300 步自主评估，按指标选模型。
- H = 16 训练在 lr 1e-4 下发散（梯度范数约 1e3），需要 lr 3e-5、预热 20。
- FP32 严格确定性；训练 = 推理。

   - V17B 的相位随训练收敛（像 V17A 从 u50 到 u100 那样）→ V17B 作为替换候选。
   - 否则 → 从 V17A 最好的 checkpoint 热启动，用 `configs/finetune_lift_h16.json` 短程微调（约 50–100 次更新），兼得结构响应与流场。
   - 相位超前仍不收敛 → 在训练损失中加入相位项（例如窗口内预测升力与 CFD 升力的互相关滞后，或位移上穿零点时刻误差），尚未实现。
4. **替换发布模型的步骤**：从 checkpoint 中只保留模型参数、模型配置和归一化量（去掉优化器状态），写入 `checkpoints/fsi_graphnet.pt`；更新 `checkpoints/MANIFEST.json`（SHA-256、训练说明）；用新模型重新推理 DEV F+ 300 步，更新 README 与第 7 节的结果表和 `docs/figures/fsi_graphnet_results.png`；GitLab `fsi-graphnet` 与 GitHub `fsi-graph` 同步推送。
5. **仍未解决的问题**：流场在约 1–2 个周期后与 CFD 失去相关；后柱周围（动网格区）有网格尺度噪声；尚未在 HELDOUT（U∞ 0.95 / 1.05）上验收，只在最终确定模型后运行一次。

### 10.5 运行环境与操作

- **主机**：两台 DGX Spark（GB10，121 GiB 统一内存）。项目根目录：97 为 `/home/briany/workspace/fsi_project`，78 为 `/home/nvidia/temp_jk/fsi_project`。登录信息不在仓库中。
- **容器镜像**：`fluid-control-physicsnemo:2.2.2`（环境变量 `FSI_IMAGE` 可改）。训练容器名即 `run_id`（如 `fsi_V17A`），评估容器名为 `eval_<run_id>_u<N>`。
- **根目录结构**：`code_releases/<tag>`（只读代码快照）、`configs/`、`tools/`、`data/{processed, splits, views}`、`models/`（热启动模型；`models/fsi-graphnet-u50/checkpoint.pt` = 发布模型）、`experiments/{recipes, runs}`。
- **监控**：
  - 训练进度：`experiments/runs/<run_id>/results/progress.jsonl`，每次更新一行（loss 及各项、H、lr）。
  - 评估进度：`experiments/runs/<run_id>/results/eval.log`，每完成一个里程碑写一行 `done <评估目录>`。
  - 评估结果：`experiments/runs/eval_<run_id>_u<N>/results/metrics.json`，`runs[0].cycles` 为逐周期指标，`runs[0].per_step` 为逐步场误差与相关；轨迹在 `results/rotation_mature2_f_plus_20261019/o000/trajectory.json`；图在 `figures/`。
  - checkpoint：`results/checkpoint_u<NNNNN>.pt`，每 25 次更新保存，保留最近 2 个以及每 50 次的里程碑。
- **停止训练**：在 `experiments/runs/<run_id>/control/` 下创建 `STOP`，训练在下一次更新开始前退出。
- **注意事项**：
  - 97 在 4 rank 训练时内存紧张，评估可能显存不足；此时把 checkpoint 复制到 78 的 `experiments/runs/IMPORT_<名称>/` 下评估。
  - 远程停止进程时不要用 `pkill -f <run_id>`，它会匹配到执行命令的 shell 本身；用 `docker stop <容器名>` 或 `STOP` 文件。
  - 新代码先用 `tools/release.sh <tag> <root>` 发布到主机，再用该 tag 生成配方。
  - GitLab 单文件上限 5 MiB，模型用 Git LFS 存储；GitHub 仓库公开，不提交登录信息和内网地址。
